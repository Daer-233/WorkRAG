# 当前资料检索的规则粗排

LangBot／MCP 调用的 `/api/v1/manuals/retrieve` 使用以下流程：

多路召回 → 按证据 ID 合并去重 → 规则粗排 → 文档候选配额 → BGE-Reranker-v2-m3 精排 → 分数门槛与证据数量限制 → 展开来源上下文。

该资料链路不再通过 RRF 计算候选名次。历史通用检索模块及向量 Provider 的融合接口仍保留；它们不是此接口调用的排序路径。

## 规则与参数

稠密向量、稀疏向量和标题／原文关键词三路各最多召回 40 条。只接受当前可读、已发布资料中的子块，并重新核对向量记录的资料 ID 和版本；这些检查是硬性约束，不能通过排序得分绕过。

规则总分由以下信号加权：

| 信号 | 权重 | 处理方式 |
|---|---|---|
| 稠密向量得分 | 0.45 | 本轮该路候选内 min-max 归一化 |
| 稀疏向量得分 | 0.30 | 本轮该路候选内 min-max 归一化 |
| 关键词匹配得分 | 0.20 | 除以本轮该路正数最大值；匹配分结合标题、适用对象与步骤原文 |
| 标题包含完整问题 | 0.05 | 大小写不敏感，匹配为 1，否则为 0 |

缺失一路的分数记为 0；某路只有一个候选或所有分数相同，归一化值记为 1；无穷大和 NaN 向量得分不参与排序。同一证据在一路多次出现时保留最高得分，不会因重复返回而累加权重。总分相同时依次按关键词得分、证据 ID 稳定排序。

此关键词评分是现有标题／原文匹配规则，不是 BM25；已审核标准问答的 BM25 快速通道保持独立。

`RETRIEVAL_COARSE_TOP_K` 控制粗排保留数量，默认 40。随后按原有文档多样性策略选择候选，`RETRIEVAL_RERANK_CANDIDATE_TOP_K` 控制送入 BGE 的预算，本机配置为 8。最终通过重排分数门槛、每份资料证据上限和 `RETRIEVAL_EVIDENCE_TOP_K` 限制返回证据；调用方可进一步缩小上限。展开父级上下文后，返回的步骤数可能多于命中的证据数。

权重是初始工程规则，尚未经过正式企业资料集调优，不代表相比 RRF 已有准确率提升。这里只做 ID 去重，没有实现跨 ID 的语义相似内容去重。

## 降级与观测

向量不可用时，关键词候选仍经规则粗排和 BGE 精排；BGE 不可用时，沿用明确标注的关键词原文降级。权限、版本和来源检查不变。

`retrieval_metrics` 新增 `coarse_method=weighted_rules_v1`、`coarse_input_count`、`coarse_count` 和 `coarse_ms`；原有 `rerank_input_count`、`rerank_ms`、`evidence_count` 保留。`hybrid_rerank` 等模式名称保留以兼容现有调用方，不表示使用 RRF。

实现位于 `apps/backend/app/manuals/coarse.py` 与 `retrieval.py`。测试覆盖分数量纲、同分／空结果、去重、候选截断、精排覆盖粗排顺序，以及现有权限、过期版本、图片来源和服务降级行为。

## 本机验证记录

2026-11-09 已重启本机资料后端并调用真实模型接口，演示资料问题返回 HTTP 200。观测到去重候选 11 条、规则粗排保留 11 条、BGE 输入 8 条、最终命中证据 2 条，`coarse_method` 为 `weighted_rules_v1`；来源上下文组装后返回 1 个资料包。此次请求只验证链路接通，不作为准确率或 P95 性能结论。
