# 2026-11-03 钉钉单聊无响应排查记录

LSD AI助手保存状态为启用，单聊消息路由仍指向工作知识助手；资料后端 8060、嵌入 8031、重排 8032 及 LangBot 容器均在运行。

机器人专属日志持续出现 `DingTalk: open connection failed`，对应时段没有消息进入 Pipeline。全局健康检查通过不能代表钉钉已连通；Box 不可用日志不是这次单聊故障的直接证据。

使用保存的凭据和相同订阅做独立 SDK 握手检查，HTTP 200，返回 endpoint/ticket；未主动发送钉钉消息，未输出票据或密钥。随后经正式管理接口重新应用该机器人的 `enable=true`，重新挂载运行时。前后凭据、模板和路由一致。

恢复后，用户在单聊发送“你好”。日志记录消息进入正确 Pipeline，成功创建卡片，并在约 17 秒内完成 14 个流式事件。用户确认看到“正在处理”并收到回复。

结论：本次直接故障是钉钉连接持续失败，重新挂载后恢复；旧连接首次握手失败的上游错误码尚未捕获，不能推断为凭据失效。未重启知识库或模型服务，未修改已有资料。后续若复现，优先查机器人专属日志及接收事件，而不是仅检查 Docker 健康状态。

诊断脚本：`scripts/diagnose-dingtalk-connection.py`（仅在 LangBot 容器执行；临时凭据副本读取后删除）。本机私有日志和配置在 `data/manuals/runtime`，不可作为普通交接附件分享。

后续已增加并启动连接自动守护，详见 `docs/history/knowledge/knowledge-connection-watchdog.md`。默认每 30 秒只读检查，满足持续失败、空闲确认、冷却和频率限制后才重新挂载；不会主动发送测试消息。
