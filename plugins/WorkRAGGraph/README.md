# 问答引擎插件使用文档

0.4.2 员工显示调整：普通回复只显示资料名称、操作步骤及必要页码，不列资料版本、证据 ID、检索命中或内部配图路径。后台完整保留结构化来源，用于权限、版本核验、图片和原文件追问。流式快照和最终／历史复用回复均经过显示过滤；实际设备编号、工单号和演示资料的虚构说明保留。

这个插件是“调试助手”和“问答流水线”共同调用的工作知识问答引擎。0.4.1 使用 LangGraph 管理记忆、资料追问、标准答案复用及证据校验，使用 Pi Agent 处理模型与工具循环。模型仍调用 LangBot 中配置的 DeepSeek，资料通过 MCP 读取 WorkRAG。

## 先分清入口

| 入口 | 用途 |
|---|---|
| 调试助手 | 本机测试问答、资料追问、个人历史和反馈事件 |
| 问答流水线 | 设置触发、安全控制、问答运行器和输出，后续供机器人绑定 |
| 问答引擎插件（这里） | 提供 LangGraph 工作流、会话记忆和插件页面 |
| 资料检索工具（原 WorkRAGReadOnly） | MCP 连接，提供四个只读工具 |
| 标准问答审核 | 编辑、发布、驳回或下架反馈形成的候选答案 |
| 入口说明 | 查看这些入口的区别及 WorkRAG 管理地址 |
| 两个标注“备用”的知识库 | 尚未配置完成的 HTTP 入口，当前助手不使用 |

连接关系：调试助手／问答流水线 → 本插件（LangGraph → Pi Agent → LangBot 授权的 DeepSeek／MCP）→ WorkRAG → PostgreSQL、Qdrant 和 BGE 模型服务。Pi 不持有模型密钥，也不获得终端、文件写入或任意业务执行权限。

## 当前已能做什么

- 使用用户在 LangBot 中配置的真实 deepseek-flash API，两个处理器均关闭模拟模式。
- 根据日常问题、工作知识、个人历史或不明确的指代，决定直接回答、调用工具或询问。
- 检索当前授权且已发布的资料，保留资料标题、版本和证据 ID。
- 处理“需要原文件”“需要截图”“下一步”等明确追问；资料不明确、动作过期或权限不足时说明原因。
- 查询当前用户自己的历史，隔离不同用户及不同机器人的记录。
- 收集明确反馈，人工审核候选后复用标准问答。
- 检查工具权限、调用次数和超时，保存会话及 LangGraph 检查点。

本机示例已通过真实 API 验收。具体覆盖问候、日常问题、知识检索、无证据、个人历史隔离、资料追问、流水线、工具权限拒绝、调用上限、真实超时以及检索后端失败和恢复。另已准备两份明确标注虚构的演示资料、6 张 PNG，验证图片字节和资料归属。

### 流式回答与附件

回答正文在模型生成时持续转发到现有卡片，不再等整轮结束后切片。分类与工具计划不展示；工作知识的流式正文先核对本轮资料，再进行不带工具的最终回答生成。审核标准答案、确定性的资料追问等可直接返回，无需人为逐字播放。模型和卡片按小块更新，不保证每次仅出现一个汉字。

确定单份资料后，回复“图片”或“文件”选择返回内容。图片、原文件通过当前钉钉原生附件通道输出，不要求发布新模板；图片每轮最多 3 张，单附件最多 12 MiB，总计最多 20 MiB。超过数量时请指定具体步骤。调试入口已实际产出 3 个 image_base64 和 1 个 file_base64；调试界面中的附件不等于真实钉钉收件验收。

现用旧钉钉模板已由用户真机确认：正文正常，相关图片默认收起，展开后可查看 3 张图并点击放大；演示 DOCX 已收到，文件打开未单独确认。图片写入当前卡片折叠区，原文件走原生文件附件。A2UI 新卡片接入停用。启动器保留正文更新兼容和 SDK 的 Message／MessageChunk 文件转换兼容修复，保留原始备份。

## 配置在哪里改

### 处理器中的 AI 能力

选择“知识问答引擎（LangGraph＋Pi）”，配置：

| 参数 | 说明 |
|---|---|
| Agent 引擎 | 当前处理器填 pi；legacy 可恢复原有模型／工具循环；不会自动故障降级或重复执行工具 |
| 回答模型 | 在 LangBot 模型页配置后选择模型；当前为 deepseek-flash |
| 助手提示词 | 工作问答的额外要求 |
| 授权的 MCP 工具 | 仅选择“资料检索工具”提供的四个只读工具 |
| 授权资料 ID | JSON 数组；空数组禁止知识检索，上传资料不会自动授权 |
| 标准答案复用 | 是否允许复用人工发布且当前仍有效的标准问答 |
| 模拟模型验收 | 当前关闭；开启后只用于模拟验收，答案带明显标记 |
| 检索数量 | 默认 5 |
| 单轮超时 | 默认 180 秒 |
| 工具调用上限 | 默认 6 次 |

调试助手和问答流水线的配置分别保存。不要在这里粘贴模型密钥，模型凭据由 LangBot 提供商配置统一管理。

### 本插件的私有配置

独立工作流数据库连接、运行范围签名密钥、授权工作区和 Pi 内部传输令牌由部署过程配置。Pi 工作进程监听本机 8062，容器使用 host.docker.internal 访问。内部传输令牌不是模型 API 密钥；不要公开任何私有配置。

## 四个 MCP 工具

| 工具 | 作用 |
|---|---|
| search_knowledge | 检索授权范围内的当前已发布知识 |
| get_document_images | 读取指定资料版本的图片引用或已确认步骤的下一步 |
| get_source_file | 获取指定资料版本的原文件引用 |
| search_my_history | 检索当前用户自己的聊天历史 |

身份及资料授权范围由运行器在服务端注入，工具端重新检查。不要给员工助手绑定 LangBot 管理 MCP。

## 资料怎么增加

1. 打开 [WorkRAG 资料管理](http://127.0.0.1:8060/knowledge/)。
2. 上传并解析资料，核对内容后发布、建立索引。
3. 把资料 ID 加入对应处理器的授权资料列表。
4. 先在调试助手询问问题，检查答案、资料版本与来源。

原始资料上传、发布和索引目前在 WorkRAG 页面完成，没有集成为 LangBot 左侧知识库的原生资料管理。LangBot 的“入口说明”页提供管理地址和对照导航。

## 反馈和标准答案

明确正反馈只进入候选库，不会自动发布。点踩保留原因；“谢谢”“好的”和无回复不视为认可。卡片模拟回调与明确语言反馈已实现，真实钉钉卡片仍待联调。

管理员进入“标准问答审核”，补完整问题、核对答案和适用范围，勾选核对项，先保存修改，再审核发布。审核 API 由 LangBot 的资源管理权限保护。下架或来源版本变化后停止复用。

当前 BM25 负责召回，只有规范化后问题一致、无额外适用条件且权限及来源有效时才直接复用；其他情况重新进入模型与检索。模拟候选不会用于真实模型模式。

## 运行和数据保存

- 同一会话串行处理，默认最多 2 个 Agent 请求同时运行，最多 32 个等待请求；重型检索串行执行。
- 待确认动作默认 10 分钟有效，执行、取消或切换话题后清除。
- 个人聊天默认保存 90 天，日常清理过期聊天和检查点；已发布标准问答独立保存。
- 工作流数据保存在独立 workrag_agent 数据库；原始资料仍由 WorkRAG 的资料库管理。
- 模型上游使用流式调用，用户侧收到核验后的分段答案，调试传输协议是 NDJSON。不会显示模型思考文本。

## 常见问题

**问答返回没有证据？** 检查资料是否发布、索引是否完成、资料 ID 是否在该处理器授权列表里。备用 HTTP 知识库的名字不会自动建立连接。

**模型或工具暂时失败？** 检查 DeepSeek 提供商配置、本机服务状态，以及“资料检索工具”是否已连接并显示四个工具。

**只拿到文件引用，没有附件？** 先确定单份资料，回复“文件”。0.3.10 会读取已发布版本原件并输出原生文件附件；多资料会先澄清。检查运行器版本和启动器的文件转换兼容检查，附件读取失败会明确提示。不要把本机预览地址当成钉钉收件证明。

**如何日常启动？** 在 G:\项目\WorkRAG 双击 start-knowledge.bat，或运行 start-local.ps1。status-local.ps1 查看状态，stop-local.ps1 停止服务并保留数据。

本机完整使用文档位于 G:\项目\WorkRAG\deployment\agent-README.md，入口对照位于 deployment\入口说明.md，真实模型验收记录位于 deployment\deepseek-acceptance.md。
