# DeepSeek 真实 API 接入验收

日期：2026-11-07，用户时区 Asia/Shanghai。插件版本 **0.3.3**，LangBot v4.11.3，插件 SDK 0.7.16。

## 已完成的配置

- “工作知识助手 · 本机验收”和“工作知识助手 · 流水线验收”均选用用户自建提供商的 **deepseek-flash**，模型 UUID `119bf144-592e-4f03-8f4f-0ce00bc65fb3`。
- 两处 `simulation=false`，默认每轮 180 秒、最多 6 次工具调用，保留原有资料白名单与四个只读 MCP 工具。
- 模型凭据仍只由 LangBot 提供商配置管理；插件通过本轮授权接口调用模型，没有将密钥复制到源码、安装包或运行器配置。
- 修改前的处理器配置保存在本机忽略目录 `data/manuals/runtime/agent-deployment/before-real-model-*.json`。未恢复用户主动删除的旧 Local Agent。

## 实际验收

真实模型通过 LangBot Runner 执行，检索经过 MCP → WorkRAG → BGE/PostgreSQL/Qdrant，并实际保存聊天与检查点。只使用“部署验收示例（非真实业务制度）”，没有向真实钉钉投递消息。

| 项目 | 结果 |
|---|---|
| 问候、日常算术 | 直接使用模型回答，路由为 daily，未调用知识工具 |
| 工作知识 | 模型主动调用 search_knowledge，返回 WRAG-LOCAL-20261107 |
| 来源核对 | 引用资料标题、local-smoke-v1 和真实证据 ID |
| 原文件追问 | get_source_file 返回 deployment-smoke.docx 引用，明确尚未投递附件 |
| 图片追问 | get_document_images 如实说明示例没有可展示图片，没有虚构图片 |
| 不明确的“需要” | 其他用户获得澄清提示，不继承前一个用户的资料 |
| 缺少知识证据 | 不编造公司火星出差补贴规定 |
| 个人历史 | 模型调用 search_my_history，能够查回自己的历史编号 |
| 用户隔离 | 另一个用户查个人历史时没有取得前一个用户的编号答案 |
| 流水线 | 正常调度、模型授权、工具授权和输出处理通过 |
| 流式传输 | 实际 NDJSON 返回 message.delta 和 run.completed，最终完成，无思考文本泄漏 |
| 工具权限拒绝 | 撤去测试处理器的工具授权后，明确返回无访问权限 |
| 工具调用上限 | 临时限制为 1 次，第二次工具请求被拦截，返回有效片段及限制说明 |
| 真实模型超时 | 临时 1 秒上限触发 Host 超时取消，未声称执行成功 |
| 真实工具失败 | 暂停受本部署管理的后端后，返回工具调用失败，而非资料不存在 |
| 服务恢复 | 后端恢复后，真实模型再次通过 MCP 检索到正确编号 |
| 连续工具证据 | 同轮知识检索后再查历史，已取得的知识证据继续保留并用于回答 |

最后核对时，临时工具权限、调用上限和超时均恢复为正常配置，全部本机服务已恢复。

## 适配修改与验证

- 显式分离 DeepSeek 的思考内容和最终文本，避免思考文本破坏 JSON 路由。工具协议需要的提供商字段仅在内部工具调用中保留，不显示给用户。
- 空模型流作为模型错误处理。未授予知识工具时明确报告权限问题。
- 文件、图片和下一步追问输出面向用户的资料信息，不展示后台规则或控制 JSON。
- 同轮连续调用不同工具时合并当前证据；新轮次仍重新判断和检索，不沿用上一轮资料来冒充本轮证据。
- 通过 **54 项**工作流与原检索回归、**5 项**真实 SDK 环境下的适配测试，以及 **17 项**真实 API 验收。

原始记录位于被 Git 忽略的 `data/manuals/runtime/agent-deployment/real-llm-acceptance.json`；流式帧位于 `real-llm-stream.json`。安装包为 `workrag-WorkRAGGraph-0.3.3.lbpkg`。

## 验收边界

这次完成的是用户指定的模型绑定和真实 API 验收。当前仅授权合成示例资料；图片覆盖的是“没有图片”分支，尚未验收真实企业图片、原文件的钉钉投递。真实企业资料导入、钉钉卡片回调、部门身份映射和业务写操作仍留待后续。

模型上游采用流式调用，员工侧在证据核验后分段输出，尚不是边生成边展示未经核验文本。路由与回答质量已通过上述样例，不代表所有企业问题均已评测。
